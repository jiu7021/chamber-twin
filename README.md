# 식각 챔버 진공 디지털 트윈

**▶ [인터랙티브 시뮬레이터 열기](https://jiu7021.github.io/etch-chamber-vacuum-twin/)**

반도체 식각 챔버의 진공 배기 상태를 압력·유량 데이터만으로 진단하려 한 프로젝트다.
공개 실측 데이터 96 웨이퍼를 분석하고, 물리 모델을 세우고,
**실제 PLC(OpenPLC)와 SCADA(Ignition)에 연동해 HIL 로 검증**했다.

---

## 한 문장 요약

> **자동 제어가 걸린 계통에서는 제어되는 값이 아니라 조종하는 값이 상태 정보를 갖는다.**
> 챔버 압력은 APC 서보가 붙들고 있어(변동계수 0.027 %) 고장을 보여주지 않았고,
> 정보를 가진 스로틀 밸브 각도는 데이터에 없었다. 그래서 물리 모델로 복원했다.

## 결과

| 항목 | 결과 |
|---|---|
| 실측 식각깊이 순번 효과 | **−2.72 % / 10 장** (p = 8.5e-26) — 확고한 신호 |
| 31개 설비 채널 전수 조사 | **이 효과를 설명하는 채널 없음** (최상위 채널도 순번 계수 흡수율 0.0 %) |
| 실측 압력 재현 | 고정 배기속도 모델 RMSE **34.8 %** → APC 모델 **8.2 %** (96/96 웨이퍼에서 우세) |
| 고장 진단 (5종) | Q_leak 오차 중앙값 **0.14 %**, S_pump/C_max/Q **0.21 %**, 검출 지연 **5.07 s** |
| RoR 실누설/아웃가싱 분리 | α 추정 **1.000 / 0.500** (참값 1.0 / 0.5), 누설만일 때 아웃가싱 올바로 기각 |
| TMP ↔ 밸브 분리 | 다중 운전점 진단으로 **오차 0.5 % 이내** 분리 (단일 운전점에서는 불가) |
| HIL 제어 루프 설계 | 위상여유 **+83.3°**, 오버슈트 7.14 % (초기 이득은 20°·22.9 % 로 부적합이었다) |
| **실제 PLC 폐루프 (HIL)** | 누설 외란에서 압력 잔류편차 **0.000 %**, 밸브각만 26.766→27.540° 이동. **해석해 27.5411° 대비 오차 0.00 %**, 정정시간 4.07 s (예측 4.1 s) |
| **SCADA 3계층** | Ignition → OpenPLC → 트윈. 설정값 변경이 밸브를 움직이고 알람까지 점등되는 것을 확인 |
| **OES 분석 (8 GB)** | 식각종인 **원자 불소(F I) 발광이 로트 내 10장당 −6 ~ −12 %** 감소, 로트마다 리셋. 순번을 통제한 편상관 r = **+0.42** (p = 1e-4) |
| 검증 | pytest **58 개** 통과 (해석해 대조 · 단위 왕복 · 추정기 식별성 · 다중 운전점) |

## 실행

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/python -m pytest tests/ -q          # 검증 58개
bash scripts/download.sh                       # 공개 데이터 내려받기 (약 10 MB)
```

웹 시뮬레이터는 정적 파일이므로 `docs/` 를 아무 정적 서버로 열면 된다.

```bash
python3 -m http.server 8766 --directory docs
```

PLC 연동은 [plc/README.md](plc/README.md) 참조.

```bash
python plc/modbus_server.py --port 5020 --local-apc   # 트윈을 Modbus 슬레이브로 노출
python plc/hil_check.py                                # PLC 제어 루프 안정성 검증
```

## 원칙

- **단위 규약**: 내부 계산은 SI 단일계(Pa, m³, m³/s, Pa·m³/s, s, K)만 쓰고 입출력 경계에서만 환산한다.
  환산 상수는 `physics/units.py` 한 곳에 모으고 유도 과정을 주석으로 단다. 왕복 테스트가 있다.
- **출처 표기**: 모든 물리 상수에 (물성치) / (통상범위) / (표준·규정) / (가정치) 를 명시한다.
  근거를 못 찾은 값은 가정치로 표기하고 민감도를 함께 보고한다.
- **테스트 우선**: 물리 엔진 구현 전에 해석해 대조 테스트를 작성했다.
- **검증 게이트**: 통과하지 못하면 다음 단계로 넘어가지 않고 실패를 그대로 보고한다.

## 알려진 한계

1. **TMP 성능저하와 밸브 마모는 *단일 운전점에서만* 분리되지 않는다.** 유량을 몇 단계 바꿔
   (Q, P, θ) 를 2점 이상 모으면 식이 선형이 되어 둘 다 풀린다 — 시뮬레이터 실측 오차 0.5 % 이내.
   앞선 보고서들이 이를 원리적 한계로 쓴 것은 과했고, 정정해 두었다.
   (포어라인 압력은 누설만 가른다. TMP 저하와 밸브 마모에는 반응하지 않는다.)
2. **압력·유량의 절대 단위가 미확정이다.** 데이터셋에 단위 메타데이터가 없어 Torr 계열과
   mbar 계열이 내부 증거로 분리되지 않는다. 모든 분석을 단위 불가지론으로 작성했다.
3. **5 Hz 샘플링은 과도응답 식별에 부족하다** (τ/dt = 1.24~1.67, 통상 요구 ≳ 5).
4. **실측 데이터에 고장 사례가 없다.** 정상 운전 96 장뿐이라 진단기의 실제 성능은 미검증이다.
5. **로트와 날짜가 완전히 교락되어 있다.** "챔버 오염 누적"과 "당일 열적 웜업"을 분리할 수 없다.
6. **OES 로도 식각깊이 변화를 설명하지 못했다.** 가장 좋은 지표로도 42 % 만 흡수되고
   순번 효과는 p = 5.5e-06 으로 남는다. 액티노메트리 기준선(Ar)이 없어 발광 세기를
   화학종 밀도로 환산할 수도 없다.
7. **PLC 장시간 안정성 미검증.** 42,793 스캔(약 71 분) 후 런타임 워치독이 걸려 멈춘 사례가
   있다. 프로그램에 반복문이 없어 "무한루프" 진단은 맞지 않으며, 원인은 규명하지 못했다.

## 쉬운 요약

반도체를 깎는 장비는 쓸수록 안쪽이 더러워져서 덜 깎인다. 언제 청소할지 알고 싶었다.
압력을 보면 될 줄 알았는데, 압력을 자동으로 일정하게 맞추는 장치가 있어서 아무것도 안 보였다.
에어컨이 24도를 맞추고 있으면 온도계로는 방이 더운지 알 수 없는 것과 같다. 에어컨이 얼마나 세게 도는지를 봐야 하는데, 그 값이 기록돼 있지 않았다.
그래서 물리 법칙으로 그 값을 계산해내는 가상 챔버를 만들었고, 진짜 PLC와 SCADA를 붙여
장비 없이 제어·감시·알람까지 시험할 수 있게 했다. 누설을 넣어보니 압력은 원래대로
완전히 돌아왔는데 밸브 각도에만 흔적이 남았고, 그 각도가 손으로 계산한 값과 소수점
셋째 자리까지 맞았다.

마지막으로, 깎는 데 쓰이는 물질(불소)의 빛까지 8 GB 어치 봤다. 로트 안에서 갈수록
어두워지는 것을 찾았지만, 식각이 얕아지는 이유를 전부 설명하지는 못했다.
